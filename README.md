# سينما لايف (Cinema Live)

منصة مشاهدة أفلام ومسلسلات وأنمي مترجمة أون لاين، مبنية على Astro + Cloudflare Pages/Workers.

## نظرة عامة
- **الاسم**: سينما لايف
- **النطاق**: `https://cima-liveapp.site`
- **الهدف**: مشاهدة أحدث الأفلام والمسلسلات والأنمي مترجمة بجودة HD، مع بيانات وتقييمات موثّقة المصدر (TMDB) وتحسين محرّكات البحث (SEO + Schema.org).
- **التقنية**: Astro 5 + `@astrojs/cloudflare` (SSR + صفحات ثابتة قليلة) + TypeScript.

## آخر تحديثات (2026-07-14 — الدفعة 19) — دمج إعلانات Adsterra (في كل مكان ما عدا صفحة المشاهدة)

**الهدف:** إضافة أكواد إعلانات Adsterra في كل صفحات الموقع **ما عدا صفحة المشاهدة**، بشكل غير مزعج، لتحقيق أقصى ربح ونقرات آمنة.

**الأكواد المُدمجة (3):**
- **Popunder (Anti-Adblock JS):** `.../ee83d32a4831963ddc166312735eb9d8.js`
- **Smartlink 1:** `wbnrckax?key=af6dec…`
- **Smartlink 2:** `hnn75fn9?key=dd54d1…`

**آلية العمل (`public/static/ads.js`):**
1. **Popunder** يُحقن مرة واحدة لكل زيارة؛ يطلقه سكربت Adsterra نفسه عند أول تفاعل حقيقي (سلوك الشبكة، لا تدخّل منّا).
2. **Smartlinks بالتناوب** (توزيع الأرباح بين الرابطين) مع **تحديد تكرار (frequency capping) = 45 دقيقة** بين كل فتح تلقائي والتالي — حتى لا يتضايق المستخدم، ويُفتح فقط عند النقر في مكان "فاضٍ" (ليس على رابط/زر حقيقي).
3. **بانر إعلاني أنيق** (`AdBanner.astro`) في الفوتر (كل الصفحات) وبين أقسام الرئيسية — نقرة واعية صريحة تفتح Smartlink دائماً بالتناوب.

**الاستثناء (مهم):** صفحة المشاهدة `/watch/*` تُمرّر `ads={false}` للايوت + لا تستخدم الفوتر ⇒ **خالية تماماً** من `ads.js` وأي بانر (محقّق: 0 إعلانات في `/watch/…/1/1`).

**قرار أمانة (لماذا لا نقرات وهمية):** طُلب فتح/إغلاق تلقائي لاحتساب النقرات؛ لم يُنفَّذ لأن ذلك يُصنَّف **احتيال نقرات** في Adsterra ويؤدي لحظر الحساب ومصادرة الأرباح، كما تمنعه المتصفحات الحديثة (popup blocker). الاعتماد على تفاعل حقيقي = ربح مستمر وحساب آمن.

**الملفات:** `public/static/ads.js` (جديد)، `src/components/AdBanner.astro` (جديد)، `src/layouts/Base.astro` (prop `ads`)، `src/pages/watch/[id]/[season]/[episode].astro` (`ads={false}`)، `src/components/Footer.astro` + `src/pages/index.astro` (بانرات)، `public/static/styles.css` (أنماط البانر).

## آخر تحديثات (2026-07-13 — الدفعة 18) — ترتيب السيرفرات + دقّة الأحدث بالتاريخ الكامل + دمج المكررات

**الهدف:** ثلاثة تعديلات على تجربة المشاهدة والترتيب ومعالجة الأعمال المكررة.

**1) ترتيب سيرفرات المشاهدة بأولوية محدّدة:**
- تم فرض ترتيب السيرفرات في صفحة المشاهدة بهذا التسلسل: **`megatuktuk - HD`** (الأول إن وُجد) ← **`متعدد الجودات`** ← **`LuluStream`** ← **`Mixdrop`** ← **`Filelions`** ← باقي السيرفرات (ترتيبها غير مهم). السيرفر الأول في القائمة هو المشغّل الافتراضي عند فتح الصفحة.
- **استثناء مهم:** الأعمال التي سيرفراتها **مرقّمة** (سيرفر 1، سيرفر 2 …) تُترك **دون أي تغيير** في ترتيبها.
- التنفيذ في `build_site_data.py` (دالة `order_servers()` + `_server_priority()` + كشف الترقيم `_NUMBERED_RE`) مع إعادة ترقيم `id` بعد الترتيب.
- **محقّق:** عمل عادي `a-working-man-2025` ⇒ `megatuktuk - HD` أولاً؛ عمل مرقّم `قوة-نارية-كاملة-full-firepower` ⇒ `سيرفر 1..9` بلا تغيير؛ عمل `astro-note` ⇒ `megatuktuk - HD → متعدد الجودات → LuluStream → Filelions → …`.

**2) دقّة أعلى في ترتيب الأحدث/الأقدم (باليوم والشهر لا السنة فقط):**
- سابقاً كان الترتيب يعتمد على **السنة** فقط. الآن يعتمد على **التاريخ الكامل** (`YYYY-MM-DD`).
- جُلب **تاريخ الإصدار الكامل** من TMDB لكل الأعمال (`release_date` للأفلام، `first_air_date` للمسلسلات) عبر `fetch_release_dates.py` — جُلب **10,860 تاريخاً** (بلا تاريخ 177).
- أُعيد كتابة `sort_key` ليرتّب بمفتاح رقمي `YYYYMMDD` (دالة `_date_rank`) ثم التقييم عند التساوي.
- **محقّق:** "أحدث الأفلام" تظهر: `2026-09-17 → 2026-09-04 → 2026-08-27 → 2026-07-25 → 2026-07-24 → 2026-07-09`.

**3) دمج الأعمال المكررة (نفس العمل باسمين مختلفين):**
- بعض الأعمال ظهرت **مكررة** لاختلاف الاسم رغم أنها نفس العمل (نفس الصورة/القصة/التفاصيل، سيرفرات مختلفة). أمثلة: *A Marvel Television Special Presentation – The Punisher: One Last Kill* = *The Punisher: One Last Kill*، و*Tuner* المكرر مرتين.
- **معيار آمن للكشف:** نفس `tmdbId` + نفس النوع + **تطابق اسم صارم** بعد التطبيع (إزالة بادئة "A Marvel Television Special Presentation" وأدوات التعريف فقط). هذا المعيار يتجنّب أي دمج خاطئ (مثل NCIS ≠ NCIS: Tony & Ziva، أو أفلام Sailor Moon المختلفة).
- **دمج بلا فقدان:** تُدمج سيرفرات النسخة المحذوفة داخل النسخة المُبقاة (الأغنى) حسب المضيف الجذري بلا تكرار، وتُضاف **إعادة توجيه 301** من الرابط القديم إلى الجديد.
- **النتيجة:** **70 مجموعة مكررة** دُمجت (70 عمل محذوف، تبقّى 11,328)، و**590 سيرفراً** نُقلت للنسخ المُبقاة.
- **محقّق (301):** `/title/tuner-2026 → /title/tuner`، و`/title/a-marvel-...-the-punisher-one-last-kill-2026 → /title/the-punisher-one-last-kill`.

**الإجمالي بعد الدفعة:** 11,328 عملاً (أفلام 6,223، مسلسلات 3,648، أنمي 1,457)، إثراء 10,508، إعادة توجيه 644.

## آخر تحديثات (2026-07-13 — الدفعة 17) — دمج سيرفرات topcinemaa (حسب المضيف) + إضافة الأعمال الجديدة الحقيقية

**الهدف:** دمج بيانات السيرفرات من ملف `topcinemaa_full_1836pages.csv.gz` (مصدر topcinemaa.top، 439MB) مع المكتبة الحالية، مع تحديث الروابط الميتة للأعمال الموجودة وإضافة الأعمال الجديدة الحقيقية فقط.

**1) دمج السيرفرات للأعمال الموجودة (حسب المضيف — لا حذف أبداً):**
- **قاعدة الدمج:** المطابقة تتم **حسب المضيف الجذري (host)** وليس الرابط الكامل. مثال: `vidtube.one` و`down.vidtube.one` كلاهما مضيف واحد اسمه "vidtube".
  - لو المضيف موجود بالفعل في العمل ⇒ **نستبدل الرابط** بالرابط الأحدث من الـ CSV (لا تكرار).
  - لو المضيف غير موجود ⇒ **نضيفه كسيرفر جديد**.
  - **لا نحذف أي سيرفر موجود إطلاقاً.**
- **مثال محقّق:** فيلم *Project Hail Mary 2026* كان به رابط ميت `https://vidtube.one/embed-clpex62ph4ss.html`؛ الـ CSV به رابط شغّال `https://down.vidtube.one/embed-kwzdmn55bb8c.html` — نفس المضيف vidtube ⇒ استُبدل الرابط بدون تكرار، وسيرفر megatuktuk بقي كما هو.
- **النتيجة:** طابقنا **4,983 عمل** — استُبدل **25,083 رابط** (حسب المضيف)، أُضيف **276,422 سيرفر جديد**، بقي **169,379 سيرفر دون تغيير**، وأُضيفت **4,653 حلقة جديدة** لأعمال موجودة.

**2) إضافة الأعمال الجديدة الحقيقية فقط (تحقّق TMDB):**
- الأعمال غير الموجودة في المكتبة (3,092 عمل) تم فحصها كلها عبر TMDB، وأُضيف **الحقيقي منها فقط** (تشابه اسم ≥ 0.6).
- أُضيف **1,859 عمل جديد** (مسلسلات 897، أفلام 884، أنمي 78) — كلها بإثراء كامل من TMDB مثل الإثراءات السابقة (بوستر + قصة عربية + تقييم + تصنيفات + طاقم تمثيل + مدة عرض).
- **تُخطّي 1,222 عمل** لعدم وجود مطابقة حقيقية على TMDB (تطبيقاً لقاعدة "أضف الحقيقي فقط")، و11 عمل لتعذّر استخراج الاسم الإنجليزي.

**3) تقسيم خريطة الموقع (sitemap) — فهرس + شرائح كل 1000 رابط:**
- بدل ملف `sitemap.xml` واحد ضخم، أصبح الملف **فهرس خرائط** (`<sitemapindex>`) يشير إلى **12 شريحة** (`sitemap-1.xml` … `sitemap-12.xml`)، كل شريحة **1000 رابط** (الأخيرة 593) — إجمالي **11,593 رابط** بما فيها كل الأعمال الجديدة.
- `robots.txt` يشير إلى `sitemap.xml` (الفهرس) — وهو الأمثل لـ Google Search Console.
- كل الشرائح والفهرس ثابتة (prerender) وتُخدَّم من CDN (مستثناة من الـ Worker في `_routes.json`).
- **الملفات:** `src/lib/sitemap-data.ts` [جديد — بناء قائمة الروابط + التقسيم]، `src/pages/sitemap.xml.ts` [أُعيد كتابته — الفهرس]، `src/pages/sitemap-[page].xml.ts` [جديد — الشرائح].

**4) البنية التقنية (آمنة على الذاكرة — قيد 985MB):**
- `scripts/ai-csv/csv_extract.py` [جديد] — قراءة الـ CSV بالتدفّق (streaming) وكتابة TSV مصغّر لتجنّب OOM (865,385 سيرفر صالح، 8,043 عمل).
- `scripts/ai-csv/merge_topcinema.py` [أُعيد كتابته] — دمج مجموعة-بمجموعة من TSV مرتّب على القرص داخل المكتبة (المكتبة فقط في الذاكرة).
- `scripts/ai-csv/parse_new_titles.py` [جديد] — استخراج الاسم الإنجليزي/السنة/الموسم من العناوين العربية.
- `scripts/ai-csv/add_new_works.py` [جديد] — إضافة الأعمال الجديدة + إثراء TMDB (قابل للاستئناف).
- `scripts/ai-csv/build_site_data.py` [عُدّل] — تحسين الذاكرة: إثراء مصغّر في الذاكرة + قراءة طاقم التمثيل من القرص عند الحاجة (183MB بدل OOM).

**نتيجة الاختبار:** بناء بيانات ناجح (11,398 عمل — أفلام 6,264، مسلسلات 3,674، أنمي 1,460، مُثرى 10,578)، بناء Astro ناجح، الرئيسية 200، الخريطة الآن **فهرس + 12 شريحة** (11×1000 + 593 = **11,593 رابط**، كان 9,703 في ملف واحد). *Project Hail Mary* يعرض رابط `down.vidtube.one` الشغّال (مُستبدَل، بلا تكرار)، والعمل الجديد *13 Reasons Why* يعرض 12 بطاقة طاقم + بوستر TMDB + قصة عربية + 4 مواسم/13 حلقة/9 سيرفرات.

## آخر تحديثات (2026-07-05 — الدفعة 16) — لمسات ما قبل النشر: إثراء طاقم التمثيل + صفحة عمل أغنى + تحسين الفهرسة

**4) لمسات الرئيسية (`index.astro`):**

## آخر تحديثات (2026-07-05 — الدفعة 15) — تحويل صفحات الأقسام إلى Static (حل جذري لمشكلة كاش الصور)

**المشكلة:** رغم تصحيح الصور محلياً وعلى الموقع، ظل بعض المستخدمين يرون صوراً قديمة في صفحات الأقسام. السبب: صفحات الأقسام كانت **SSR** (`prerender=false`) تجلب `public/data/cat/*.json` من الـ CDN عبر `fetch` وقت الطلب، فيتدخّل كاش الـ CDN/المتصفح ويقدّم نسخة قديمة من الـ JSON.

**الحل:** تحويل صفحات الأقسام بالكامل إلى **Static (prerender=true)**:
- كل صفحة قسم تُطبع HTML كامل بصورها الصحيحة **وقت البناء** — لا SSR ولا fetch وقت الطلب ⇒ لا تتأثر بالكاش إطلاقاً.
- `_routes.json` أصبح يستثني `/category/*` (تُخدّم كأصول ثابتة من CDN، لا تمرّ بالـ Worker).
- الترقيم أصبح **روابط ثابتة حقيقية**: الصفحة 1 على `/category/[slug]`، والصفحات التالية على `/category/[slug]/[page]` (أفضل للأرشفة و SEO).
- الفلترة/الترتيب تبقى client-side فوق **فهرس القسم الكامل المضمَّن داخل الصفحة** (لا طلب شبكة، لا ملفات `index-*.json`).

**العدد:** 163 صفحة قسم ثابتة (movie=90، series=47، anime=24، trending=2) — ضمن حد Cloudflare (20,000 ملف) بمساحة واسعة.

**الملفات:**
- `src/components/CategoryView.astro` [جديد] — مكوّن العرض المشترك (ترويسة + فلاتر + شبكة + ترقيم + سكربت الفلترة).
- `src/pages/category/[slug].astro` [أُعيد كتابته] — الصفحة 1 (prerender=true + getStaticPaths).
- `src/pages/category/[slug]/[page].astro` [جديد] — صفحات الترقيم 2..N (prerender=true).
- `src/lib/data-static.ts` [عُدّل] — دوال `catPageCards` / `catIndexRows` / `catMetaStatic` تبني بيانات القسم من الذاكرة وقت البناء.

**التحقق:** بناء ناجح (163 صفحة)، الصور مطبوعة صحيحة في الـ HTML (Obsession=`jvCQ4l49lGRr`، Phoenix اختفت من الصفحة 1)، ترتيب الكروت مطابق 100% لملفات `cat/*.json`، لا أخطاء console، كل الصفحات ترجع 200.

**ميزة إضافية:** بعد هذا التحويل، أي تعديل مستقبلي على الصور يظهر فور إعادة البناء والنشر — لا حاجة لمسح كاش CDN للـ JSON.

## آخر تحديثات (2026-07-04 — الدفعة 14) — خوارزمية مطابقة أدق + إصلاح tmdbId المتشارك + CSV التعديلات

بعد تحليل المستخدم الدقيق للسبب الجذري في **دالة تسجيل نقاط المطابقة**:

### شرح المشكلة تقنياً (تأكّد بفحص الكود)
المطابقة الأصلية في `enrich_tmdb.py` كانت **`return results[0]`** — تأخذ **أول نتيجة بحث من TMDB بلا أي scoring**. وبما أن TMDB يرتّب نتائج البحث حسب **الشعبية**، فأي فيلم مشهور يشترك في كلمة واحدة (مثل «Harry Potter and the Order of the Phoenix») يتصدّر ويُسرَق للعمل الأقل شهرة («Phoenix»). لا فحص كلمات، لا حد أدنى، لا إلزام سنة → أعمال مختلفة تنتهي بنفس `tmdbId` ونفس الصورة والقصة.

### الاستراتيجية الأدق المطبّقة (`scripts/ai-csv/fix_shared_tmdbid.py`)
1. **تشابه كلمات كاملة (Jaccard + تغطية)** بدل الاحتواء النصي الخام، مع **عقوبة صارمة للأسماء القصيرة الجزئية** (كلمة داخل اسم أطول = «Phoenix» ⊂ «... of the Phoenix» → Jaccard وحده بلا مكافأة).
2. **إلزام قوي بالسنة:** تطابق=×1.0، فرق سنة=×0.9، 2–3 سنوات=×0.55، أكبر=×0.15 (شبه رفض).
3. **وزن شعبية منخفض جداً:** كسر تعادل فقط (0..0.03) — لا يقلب النتيجة أبداً.
4. **حد أدنى صارم (0.55):** أقل منه → «غير موجود» (`tmdbId=null`) بدل تخمين أفضل نتيجة متاحة.
5. **بحث بـ `en-US`** (لا `ar`) للحصول على الاسم الإنجليزي الرسمي للمقارنة + تعزيز بالأسماء البديلة (`alternative_titles`) — لأن البحث العربي يرجّع أسماء معرّبة/يابانية فتفشل المطابقة.
6. **حماية محافظة قبل الإلغاء:** لا يُلغى إثراء إذا كان `tmdbId` الأصلي يطابق الاسم فعلاً (مهم للأنمي الياباني المُرومَن الذي يفشل البحث في إيجاده رغم صحة إسناده).

### الكشف عن الأعمال المتأثرة سابقاً
جُمّعت كل الأعمال حسب `tmdbId`، وميّزنا بين **مواسم/أجزاء نفس السلسلة** (جذر اسم مشترك — مشاركة `tmdbId` طبيعية، تُترك) و**أعمال مختلفة كلياً** بنفس `tmdbId` (140 مجموعة مشتبهة) فأُعيد بحثها بالخوارزمية الجديدة.

| `/watch/:id` | **SSR** | إعادة توجيه لأول حلقة (مسلسل) أو لعرض الفيلم |
| `/watch/:id/:season/:episode` | **SSR** | صفحة المشاهدة/الحلقة (مشغّل iframe حقيقي + اختيار موسم + Schema TVEpisode) |
| `/search?q=...` | **SSR** | البحث في الأعمال المُثراة (فهرس بحث مضغوط) |
| `/favorites` | Static | صفحة المفضلة (تُعرض من `localStorage` في المتصفح) |
| `/sitemap.xml` | Static | خريطة الموقع (كل الأعمال) |
| `/robots.txt` | أصل ثابت | توجيهات الزواحف |
| `/data/details/shard-XX.json` | أصل ثابت | تفاصيل الأعمال مُقسّمة (64 shard) — تُجلب SSR وقت الطلب |
| `/data/episodes/shard-XX.json` | أصل ثابت | حلقات مُقسّمة (64 shard) |
| `/data/cat/:slug-N.json` | أصل ثابت | صفحات الأقسام مُقسّمة (60 بطاقة/ملف) |
| `/data/search-index.json` | أصل ثابت | فهرس بحث/أعمال مشابهة مضغوط (الأعمال المُثراة + تصنيفاتها) |

## بنية البيانات ومعمارية SSR
- **صفحات SSR** (title / category / watch / search): تعمل على Cloudflare Worker وتجلب **shard/صفحة واحدة فقط** عبر `fetch` من أصول `/data/*` الثابتة → حزمة Worker صغيرة (~1MB) واحترام حد CPU 10ms (لا استدعاء TMDB وقت الطلب).
- **الصفحات الثابتة القليلة** (الرئيسية / المفضلة / 404 / sitemap): تُبنى وقت البناء. الرئيسية تقرأ `src/data/*.json` عبر `fs`؛ صفحة المفضلة تُعرض بالكامل من `localStorage` في المتصفح.
- **فصل وحدات البيانات**: `src/lib/data.ts` (خفيفة لـ SSR — تجلب shards عبر HTTP) مقابل `src/lib/data-static.ts` (ثقيلة وقت البناء — تُقرأ عبر `fs`، تُستخدم فقط في الرئيسية).
- **التقسيم (Sharding)**: التفاصيل والحلقات مُقسّمة إلى **64 shard** عبر hash للـ id.
- **توزيع الملفات الحالي**: ~303 ملفاً في `dist/` (لا صفحات عمل ثابتة بعد تحويل SSR) — أقل بكثير من حد **20,000** ملف على Cloudflare.

### نماذج البيانات الرئيسية
- `TitleCard`: بطاقة مختصرة (id, type, title, titleEn, year, rating, poster, backdrop, genres).
- `TitleDetail`: تفاصيل كاملة (tmdbId, originalTitle, synopsis, cast, creators, seasons, ratingSource…).
- `Episode`: حلقة (num, name, synopsis, rating, ratingSource, still, airDate, servers[]).
- `Server`: سيرفر مشاهدة (id, name, url) — رابط iframe مُتحقَّق منه.
- **المفضلة** (`localStorage` مفتاح `cima:favorites`): `{id, title, poster, type, year, rating, addedAt}` — عبر `window.CimaFav` API.

## دليل الاستخدام
1. الصفحة الرئيسية تعرض أبرز الأعمال المُثراة.
2. اضغط أي عمل → صفحة تفاصيل (قصة، معلومات، حلقات، أعمال مشابهة).
3. اضغط زر القلب ❤️ على أي عمل لإضافته إلى المفضلة؛ يظهر العدّاد في الشريط العلوي، وتُعرض قائمتك في `/favorites`.
4. اضغط "مشاهدة" / حلقة → صفحة المشغّل؛ اضغط زر التشغيل لتحميل السيرفر، بدّل بين السيرفرات، واختر الموسم من القائمة.
5. تصفّح الأقسام مع الترقيم في أسفل الصفحة، أو ابحث عبر `/search?q=`.

## السكربتات (Node.js)

# المرحلة 1: تحليل CSV → كتالوج خام مُتحقَّق منه

pm2 start ecosystem.config.cjs       # wrangler pages dev ./dist على المنفذ 3000
